# Что в проекте отсутствовало — и что теперь формализовано

Ревизия проведена по всем источникам, лежащим в репозитории: четыре PDF-кодекса
OSA-4.0 (`POLYMATH_ATLAS_OSA4_Architectural_Codex.pdf`,
`POLYMATH_ATLAS_OSA4_Unified_Codex.pdf`, `POLYMATH_ATLAS_OSA4_Full_Unified_Codex.pdf`,
`POLYMATH_ATLAS_OSA4_Imperial_Master_Dossier.pdf`), стенограммы (`Text Document.txt`,
`Text Document (2).txt`), `POLYMATH_ATLAS_AGI_PROTOTYPE_v08.json` и уже существующие
Lean-модули.

**Главная находка ревизии.**  Слой **OSA-4.0 (Semantic Kernel v0.3.1 / v0.4)** не был
формализован вообще: в Lean-исходниках не встречалось ни одного упоминания OSA-4.0,
законов LAWBOOK, WP-трансформера, алгебры идентичности, эпистемической решётки и
Semantic Torture Set T01–T15.  Формализован был только предшествующий слой OSA-3.2
(`RequestProject/OSA/`), который сами кодексы помечают как `LEGACY`.  Этот пробел
закрыт: добавлен модуль `RequestProject/OSA4/` (11 файлов).

## 2. Дефект спецификации, найденный при формализации

Кодекс утверждает: «Доказаны идемпотентность, коммутативность и ассоциативность»
напечатанной пятизначной таблицы слияния ветвей.  В Lean проверено:

* `joinSpec_idem`, `joinSpec_comm` — **верно**;
* `joinSpec_not_assoc` — **ассоциативность не выполняется**.  Явный контрпример:

      (TRUE ⊔ FALSE) ⊔ UNKNOWN = CONFLICT,    TRUE ⊔ (FALSE ⊔ UNKNOWN) = UNKNOWN.

  Неассоциативных троек ровно восемь (`joinSpec_assoc_failures_card`), и каждая
  содержит пару `TRUE`/`FALSE` (клетка, дающая `CONFLICT`) вместе с `UNKNOWN` или
  `ABSENT` (`specAssocFailures_shape`).

Причина структурная: строка `UNKNOWN` делает «нет информации» поглощающим элементом
(то есть `TRUE ≤ UNKNOWN`), а клетка `TRUE ⊔ FALSE = CONFLICT` требует, чтобы
наименьшей верхней гранью `TRUE` и `FALSE` был верхний элемент.  Одно значение не
может быть одновременно «нет информации» и «верхняя грань».

**Исправление** следует собственному принципу кодекса «Presence ≠ Truth»:
свидетельства о присутствии ресурса и об истинности предиката разведены, слияние —
объединение свидетельств (`Belief.join`).  Полурешёточные законы становятся
теоремами (`join_idem`, `join_comm`, `join_assoc`, наименьшая верхняя грань,
независимость от порядка и повторов ветвей).  При этом сохраняются ключевые
вердикты Torture Set: T09 (`TRUE ⊔ FALSE = CONFLICT`), T08
(`TRUE ⊔ ABSENT = UNKNOWN`), T05 (`UNKNOWN ≠ FALSE_KNOWN`).  Расхождение с
напечатанной таблицей локализовано и доказано: ровно шесть клеток, все в
строке/столбце `UNKNOWN` (`spec_disagreement_eq`), вне `UNKNOWN` таблицы совпадают
(`collapse_join_eq_spec_of_ne_unknown`).

## 3. Semantic Torture Set: вердикты вычислены

| кейс | сценарий | доказанный вердикт |
|---|---|---|
| T01 | MEASURE → CALIBRATE → MODEL без доказанной достаточности | `UNDECIDABLE` (заявленный в первичном прогоне PASS был ошибкой) |
| T01′ | то же с `CHECK_SUFFICIENCY` | `PASS` |
| T02 | CREATE X → CREATE Y → DELETE X → ANALYZE Y | `PASS` |
| T03 | CREATE X → DELETE X → ANALYZE X | `REJECT / E_LIVENESS_VIOLATION` |
| T04a / T04b | resurrection (тот же ID) / recreation (новый ID + provenance) | запрещено / допустимо |
| T05 | MEASURE → MODEL, достаточность неизвестна | `UNDECIDABLE` |
| T06 | достаточность 0.20 < 0.80 | `REJECT / E_PRECONDITION_FALSE` (и `PASS` при 0.90) |
| T07 | оператор вне реестра | `REJECT / E_UNKNOWN_OPERATOR` |
| T08 | ветви «объект есть» / «объекта нет» | `UNKNOWN` (presence ≠ truth) |
| T09 | ветви TRUE / FALSE | `CONFLICT` |
| T10 | ветви X = 10 / X = 11 | существование известно, значение — нет |
| T11 | CALIBRATE → MODIFY → USE | `REJECT / E_LIVENESS_VIOLATION` |
| T12 | двойное CONSUME | `REJECT / E_INVARIANT_VIOLATION` |
| T13 | DECIDE → EXECUTE без авторизации | `REPAIR`; после вставки AUTHORIZE — `PASS`; при доказанном отказе — `REJECT / E_AUTH_DENIED` |
| T14 | ремонт существует, обязательство остаётся | `UNDECIDABLE` (а `REPAIR` — когда ремонт действительно закрывает обязательство) |
| T15 | дёшево-небезопасно против дорого-безопасно | выбирается безопасный вариант |

Кроме того доказано, что компилятор нетривиален: реализуются все четыре вердикта
(`verdicts_all_realized`), REJECT всегда снабжён кодом ошибки (`reject_has_code`),
а PASS означает прохождение всех структурных проверок.

## 4. Что закрыто последней ревизией

1. **Минимальный базисный набор §13 — закрыт полностью.**  Кодекс требует по
   пять видов проверки (positive / negative / boundary / branch / repair) на
   каждый из 18 законов — 90 позиций.  Ранее было закрыто 51; недостающие 39
   позиций теперь снабжены доказанными свидетелями
   (`RequestProject/OSA4/BasisWitnesses.lean`), а учёт зафиксирован машинно:
   `coverage_card = 90`, `coverage_complete` (перебором: у каждого закона есть
   свидетель каждого вида), `coverage_remaining = 0`, `fullyProbed_eq`
   (положительный и отрицательный свидетель есть у всех восемнадцати законов).
2. **MODEL CHECK ядра — выполнен** (`RequestProject/OSA4/ModelCheck.lean`).
   Кодекс ставит `MODEL CHECK` отдельным этапом перед закрытием Kernel v0.4.
   Законы проверены не только в общем виде, но и исчерпывающим перебором на
   конечных областях: алгебра предикатов `PT` (все 4³ тройки), моноид уровней
   эффекта (5³), алгебра свидетельств `Belief` (16³), алгебра идентичности
   (все 25 миров над двумя идентификаторами × 12 шагов × 2 идентификатора:
   LAW-004, LAW-005, LAW-016, однократность потребления, недостижимость
   воскрешения), состояние и WP (6 операторов × 6 состояний × 11 предикатов:
   LAW-003, LAW-006, LAW-010, LAW-011, LAW-012, LAW-017) и компилятор на
   конечном наборе сценариев (REJECT всегда с кодом, PASS — только после всех
   структурных проверок, реализуются все четыре вердикта).

   **Находка перебора.**  Четырёхзначная алгебра предикатов `PT` не
   дистрибутивна и не удовлетворяет закону поглощения: нарушающих троек ровно
   две, обе — на встрече `UNKNOWN` с `CONFLICT` (`pt_and_not_distrib_or`,
   `pt_distrib_failures_eq`, `pt_absorption_fails`).  На фрагменте без
   `CONFLICT` алгебра замкнута и является дистрибутивной решёткой
   (`pt_conflict_free_closed`, `pt_conflict_free_distrib`,
   `pt_conflict_free_absorption`), поэтому дефект не затрагивает состояний, в
   которых противоречие ещё не зафиксировано, и ни одно из доказанных
   утверждений ядра на дистрибутивность не опирается.  Итог перебора сведён в
   `kernel_model_check` и `model_check_findings`.
3. **Замыкание Kernel v0.4 и Atlas S-1.0 Meta-Schema**
   (`RequestProject/OSA4/MetaSchema.lean`).  Кодекс требует порядка
   `KERNEL → LAWBOOK → MINIMAL BASIS TORTURE SET → MODEL CHECK →
   KERNEL v0.4 (closed) → ONLY THEN Atlas S-1.0 Meta-Schema` и держит схему в
   статусе `FROZEN / DEFERRED`, пока замыкание не достигнуто.  Замыкание
   теперь доказано (`kernel_v04_closed`: 18 законов — теоремы, базис §13
   полон, MODEL CHECK пройден), поэтому шлюз открыт законно
   (`metaSchema_gate_open`), и схема построена.

   Главное требование кодекса — «Meta-Schema должна быть сериализацией уже
   определённой математики, а не местом, где математика впервые появляется» —
   формализовано и доказано: значения ядра переводятся в примитивный обменный
   формат (строки, числа, булевы значения, списки) и восстанавливаются точно
   (`axes_roundtrip`, `lawId_roundtrip`, `pred_roundtrip`, `op_roundtrip`,
   `kstate_roundtrip`, `chain_roundtrip`), сериализация цепочки не меняет
   вердикта компилятора (`chain_wire_verdict`), а каталог узлов схемы находится
   во взаимно однозначном соответствии с перечнем понятий ядра
   (`metaSchema_bijective`): ни узла без математического источника, ни понятия
   ядра без узла.  Сводка — `metaSchema_is_faithful_serialization`.

## 4a. Что осталось незакрытым (честный список)

1. **Три открытые проблемы кодекса** — формализации не подлежат по существу, и
   кодекс это фиксирует сам:
   * *Интерпретация*: контекст бесконечен, смысл не типизируется;
   * *Модель агента*: компетенция и юрисдикция — социальные конструкты;
   * *Валидация цели*: формальная система не оценивает этичность или истинность
     самой цели.
   Там, где такое утверждение всё же ограничивает объекты, ограничение
   формализовано (например, «принятие изменения — за человеком»:
   `acceptance_is_human`, `llm_owns_no_graph_authority`).
2. **Пункты аудита V100 #3346–#3348, #3350–#3357, #3359–#3360, #3362–#3364,
   #3366–#3368, #3370.**  Их текста в репозитории по-прежнему нет (см.
   `POLYMATH_ATLAS_V100_AUDIT_FORMAL_MAP.md`); строки оставлены открытыми, а не
   заполнены догадками.
3. **Оговорка о MODEL CHECK.**  Перебор исчерпывающ на указанных конечных
   областях (они выписаны явно в `ModelCheck.lean`), а не на всех возможных
   мирах, состояниях и цепочках; общие формы законов доказаны отдельно в
   `Lawbook.lean`.
