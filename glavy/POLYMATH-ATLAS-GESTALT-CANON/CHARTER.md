# УСТАВ ДОМА — CANON CHARTER

**POLYMATH-ATLAS-GESTALT-CANON / Lean 4.28.0 / Mathlib v4.28.0**

> Принцип дома: **не максимальная убедительность текста, а максимальная
> трассируемость, проверяемость и честность границ знания.**
> Дом — не проект на честном слове. Дом — автомат: устав исполняет машина,
> а не память и не настроение.

---

## §2. Стратификация истины (8 классов)

Ни один класс не смешивается с другим — ни в текстах, ни в коммитах:

| Класс | Значение | Кто несёт ответственность |
|---|---|---|
| `DEFINITION` | соглашение об обозначениях | автор файла |
| `THEOREM` | машинно-проверенное утверждение | ядро Lean |
| `HYPOTHESIS-RELATIVE` | верно ПОСТОЛЬКУ, поскольку верна гипотеза | должен быть явен (`§5`) |
| `COMPUTABLE TEST` | вычислимая проверка на конкретной модели | запуск, не доказательство |
| `COUNTEREXAMPLE` | контрпример, закрывающий утверждение | ядро Lean |
| `EMPIRICAL CLAIM` | утверждение о мире вне Lean | источник обязателен |
| `INTERPRETATION` | смысловая надстройка над формой | помечается как интерпретация |
| `OPEN` | открытый вопрос | запрещено закрывать искусственно (`§8`) |

## §3. Аксиомная дисциплина

**Разрешённый аксиомный след** любой константы дома:

```
{ propext, Classical.choice, Quot.sound }
```

Запрещено под страхом красного CI:

1. `sorry` / `admit` — незакрытая теорема → зависимость `sorryAx`;
2. `native_decide` — доверие компилятору → зависимость `Lean.ofReduceBool`;
3. объявления `axiom` — самодельные аксиомы запрещены вовсе;
4. любые иные аксиомные зависимости, пришедшие извне.

Проверяется **не декларацией, а исполнением**: автомат `CANON-AUTOMATON`
проходит по каждой константе каждого модуля и вычисляет транзитивный
аксиомный след (`Lean.collectAxioms`). Ловится всё: забытый `sorry`,
скрытый `native_decide`, самодельная аксиома, даже неиспользуемая.

## §4. ДОМ = АВТОМАТ

Договор дома — конечный автомат:

```
Q      = { ЧИСТО, ГРЯЗНО }
Σ      = push-события в main
δ:     ГРЯЗНО × отказ_любого_гейта        → ГРЯЗНО
       ГРЯЗНО × зелёная_четвёрка_гейтов   → ЧИСТО
       ЧИСТО × отказ_любого_гейта         → ГРЯЗНО
q₀     = ЧИСТО  (первый коммит дома)
Инвариант дома: state(main) = ЧИСТО
```

Четвёрка гейтов (все обязаны быть зелёными):

| Гейт | Что проверяет | Исполнитель |
|---|---|---|
| G-build | дом собирается ядром целиком, все 301 модуль | `lean-action` + Mathlib-кэш |
| G-sweep | аксиомный след каждой константы ⊆ разрешённой тройки | `scripts/gen_sweep.py` + `scripts/axiom_sweep_body.lean` |
| G-report | текстовые запреты §3, статистика, отчёт | `scripts/charter_report.py` |
| G-mirror | вычислимые свидетели слоя Gestalt согласны с Lean | `runtime/gestalt_verification.py` |

Красный гейт = состояние ГРЯЗНО = чинить до нуля вопросов, а не описывать.

## §5. Гипотезно-относительное моделирование

Вместо сокрытия допущений — их явная трассировка:

```lean
structure Model where
  postulate : Prop   -- допущение объявлено полем, а не аксиомой
```

Каждое утверждение, верное лишь при допущении, помечается классом
`HYPOTHESIS-RELATIVE` и остаётся параметризованным моделью. Никаких
«временных аксиом», которые потом забывают убрать.

## §6. Протокол аудита (9 фаз)

1. Инвентаризация артефактов.
2. Сверка с исходниками (source scan).
3. Сборка (`lake build`) — всё или ничего.
4. Аудит теорем (`#print axioms`-серия / полный свип).
5. Аудит аксиомного следа (§3).
6. Рантайм-проверки (вычислимые свидетели).
7. Контрпримеры и «пытки» (`Torture20`, `Torture25`).
8. История (`git log`) — прослеживаемость изменений.
9. Сводный отчёт с вердиктами по каждому классу §2.

## §8. Открытые вопросы

Вопросы `O01–O03` (`RequestProject/OSA4/OpenQuestions.lean`) — **OPEN**.
Запрещено их искусственное закрытие: превращение в теоремы без доказательства,

## §9. Процедура изменений

1. Любое изменение канона — через коммит в `main`.
2. Автомат пересобирает дом и перепроходит все гейты.
3. Красный автомат = изменение не принято, что бы оно ни обещало.
4. Изменение Устава — отдельный коммит с обоснованием в теле.

## §10. Свежесть

`watchdog.yml` каждую неделю сравнивает пин дома (`lean-toolchain`,
`lakefile.toml`) с мировым краем (релизы `leanprover/lean4`). При появлении
новой версии открывается issue. **Апгрейд — отдельная операция перекрёстной
проверки всех модулей, а не «уборка»**; пока проверка не зелёная — дом стоит
на своём пине и гордится этим.
